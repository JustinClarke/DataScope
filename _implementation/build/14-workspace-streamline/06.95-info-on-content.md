# S6.7 — Info opens on content

**Tier:** v0.70 (the workspace streamline, D73 execution) · **Master spec:** §13.3 (the bottom
region — Info's visibility and content; the tab registry) · **Decision row:** D73 (no row is
reversed at the decision level; §13.3's own charter is scoped further, and its tab-registry
paragraph gains an eighth singleton — same discipline S5 used adding the `query` artifact type)
· **Depends on:** S6.5 (shipped 2026-07-29) · **Gated by S0:** no.

**Prompted by a direct human report against the shipped S6.5 drawer**, not assumed: Info is
permanently visible even with nothing selected and nothing run, which reads as two dead panels
side by side on first open; and once a query does run, the result sits underneath a "Select a
table, column, or relationship to inspect it." sentence and an "Export recipe" button that have
nothing to do with it — the same clutter the human named directly against a screenshot.

## Objective

Make Info's presence answer to whether there is anything to show it, rather than to the drawer
merely being open — and once it is showing something, make that something exactly the result: no
chart, no inline history, a **Pin to tab** worth noticing. Concretely:

- **Info is absent, not empty, by default.** No selection and no console run this session ⇒ no
  Info pane and no divider; the SQL pane takes the drawer's full width. A selection or a run —
  the same two events S6.5 already tracks via `openInfo()` / `activateConsole()` — is what makes
  it appear.
- **The empty console invites the first query**, instead of showing a blank editor beside a
  blank Info: a placeholder line naming a real, already-loaded table.
- **Info shows the result and nothing past it.** The chart S6.5 put beside the grid and the
  inline history disclosure both move out; **Pin to tab** becomes the one clear, primary action
  directly above the grid, and a **History** button beside it opens the session's run log in its
  own tab.

## Scope calls

**1. Info's visibility is derived, not permanent — reversing S6.5 scope calls 3 and 5 at the
visibility level only.** S6.5 argued Info must never reach zero width because "a run landing in
an invisible pane is how a user confirms a transform through the guard modal and then never sees
what it did," and built that guarantee as *both panes always visible*. The guarantee is kept, not
dropped: `InspectorDrawer` computes `hasInfoContent = lastSelectionKind !== null ||
useQuerySession(CONSOLE_SESSION).status !== 'idle'`, and a run is one of exactly the two things
that can make it true — so a run still can never land somewhere the user can't see, it just no
longer shares the guarantee with an idle, contentless pane sitting there regardless. `false`
renders no Info pane and no divider; the SQL pane's flex basis goes to the drawer's full width.
`infoRatio`'s clamp, the drag handle and expand-to-stack are otherwise untouched — they govern
the split once it exists, not whether it does.
*Why this doesn't flicker:* `status` only returns to `'idle'` via `clearResult`, fired solely on
a run superseded/aborted by the run that replaces it (`services/sql.ts`) — which sets `'running'`
again in the same tick, so there is no user-visible moment where a mid-session Info closes.

**2. The empty console gets a placeholder, not `QuerySuggestions` back.** Human call — deliberately
*not* reopening S6.5 scope call 8, which pulled the suggestions block out of the console this same
week for being "the single largest contributor to the reported scroll distance" and gave it
exactly one home (the map, S6). A static Monaco placeholder decoration — `Type a query, or
⌘Enter to run — try SELECT * FROM "<first loaded table>" LIMIT 100`, the table name read from the
live dataset registry, no ranking, no card, no click target beyond the editor itself — costs
nothing to build and does not reintroduce the component S6.5 just removed.

**3. Info is scoped down to the result — no chart, no history.** Scopes Info's charter one level
further than S6.5 did. S6.5 moved `AutoChartPanel` and the inline `QueryHistory` `<details>` into
Info alongside the grid, on the reasoning that "what a query produced" was one thing. Reversed
here: a chart is a *different view* of the result and a session-wide history log is *every*
result this session — neither is "this result," and both were competing for room in a pane that,
per scope call 1, now only exists because there is a result to show. `QueryOutput` (inside Info)
stops rendering `AutoChartPanel`; `DrawerInfo` stops rendering the `<details>` History block.
`ResultsGrid` itself is untouched — still sortable, paginated, scrolling on both axes, still
growing into whatever room `expanded` gives it. A chart already has its own destination (the
`charts` tab); this call does not invent a second one for Info.

**4. The scent strip doesn't mount with nothing to show.** `DrawerInfo` renders `<Inspector/>`
only when `lastSelectionKind !== null`. Today's "Select a table, column, or relationship to
inspect it." fallback stays inside `Inspector.tsx` rather than being deleted — but in practice
this removes it from ever sitting above a bare result, which is the complaint it was named for.

**5. Pin to tab leads; History and Export recipe stop being its peers.** `SessionActions` splits
by what each button is *about*. **Pin to tab** is result-scoped — promoting what just ran — so it
becomes Info's one primary, amber-styled action, positioned directly above `QueryOutput`'s
Results header. **History** and **Export recipe** are both session-scoped — "every result this
session" and "every derived table this session," respectively — so they move down together, out
of the row a fresh result leads with. History's button now opens a tab (scope call 6) instead of
the disclosure scope call 3 just removed; Export recipe keeps its existing `downloadRecipe`
behavior and disabled-when-no-derived-tables state unchanged.

**6. History is promoted to a singleton tab — the registry amendment, not a new mechanism.**
`TabType` gains `'history'`, its **ninth member and eighth singleton** (`TAB_KIND.history =
'singleton'` — one log, never per-table, same reasoning `map` / `pivot` / `export` already carry;
`TAB_GLYPH.history` a monochrome `lucide-react` icon, the dingbat set staying closed at six per
`types/tabs.ts`'s own comment). The tab's content is the existing `QueryHistory` component,
**unmodified** — `useQueryStore`'s `history` array is already session-wide across every session,
not console-only (`stores/query.ts`: "Session-wide, not per-session: one log of what ran this
session"), so relocating its render target changes nothing about what it shows. Its rows already
carry `RunSqlButton`, which already calls `runInConsole` — sets the console buffer, opens the
drawer, runs it. Combined with scope call 1, clicking an old query now visibly lands its answer
in Info **for free**: no new run path, no new pin path. "Opens on Inspector first, then a new tab
if you want it kept" is scope call 1 plus the existing, unmodified `pinConsoleQuery` — this call
adds only the tab type and the button that opens it.

## Spec

### `src/types/tabs.ts`

```ts
export type TabType =
  | 'map' | 'profile' | 'query' | 'pivot' | 'charts' | 'correlation' | 'export' | 'ingestion'
  | 'history'; // new — S6.7, eighth singleton

// TAB_KIND.history = 'singleton'
// TAB_GLYPH.history = { kind: 'icon', Icon: History } // lucide-react
```

`HISTORY_TAB_SUBJECT` follows `MAP_TAB_SUBJECT`'s existing fixed-subject pattern
(`WorkbenchShell.tsx`) — a constant, not a per-table key, since there is exactly one log.

### `src/stores/drawer.ts`

No new fields. `hasInfoContent` is computed where it's consumed (`InspectorDrawer.tsx`), reading
`useSelectionStore` and `useQuerySession(CONSOLE_SESSION)` — both already imported by Info's
current siblings — rather than duplicated into the drawer store, which stays geometry-only.

### `src/features/inspector/InspectorDrawer.tsx`

- Computes `hasInfoContent` as scope call 1 describes; when false, renders `SqlModule` alone at
  full width, no divider, no `PaneHeader label="Info"`.
- Everything else (`expanded`, `infoRatio`, drag handles, the narrow-drawer stack) is unchanged
  and applies only once `hasInfoContent` is true.

### `src/features/inspector/DrawerInfo.tsx`

- `<Inspector/>` gated on `lastSelectionKind !== null` (scope call 4).
- `SessionActions` splits into a primary row (**Pin to tab** alone, directly above
  `QueryOutput`) and a secondary row (**History**, **Export recipe**) beneath or beside it —
  exact placement is a build-time call, not a doc-time one; the header hierarchy (primary vs.
  secondary) is what's decided here.
- The `<details>` History block is deleted.

### `src/features/sql/QueryResultsPanel.tsx`

- `QueryOutput` stops rendering `AutoChartPanel`. `QueryHistory` is unchanged internally and
  exported as today — its new caller is the history tab, not `DrawerInfo`.

**Build-time deviation (2026-07-29), recorded rather than silent:** `QueryOutput` is shared by the
console's Info pane, Pivot and every query tab, so deleting its chart outright would have stripped
charts from surfaces this leaf never examined — a query tab is full-canvas and has the room the
chart was crowding out of Info. Landed instead as a `showChart` prop defaulting to `true`, passed
`false` from exactly one call site (`DrawerInfo`). Scope call 3 holds as written for Info; the
non-goal ("no chart re-added to Info, ever, by this leaf") is unaffected.

### `src/features/sql/HistoryTab.tsx` (new)

- Thin: a tab-appropriate heading plus the existing `<QueryHistory/>`. No new data-fetching, no
  new state.

### `src/app/WorkbenchShell.tsx`

- Gains a `case 'history'` in the tab-content switch (alongside `pivot` / `charts` / `export`'s
  existing cases), rendering `<HistoryTab/>`. The **History** button in `DrawerInfo` opens it via
  `useTabsStore.getState().openTab('history', HISTORY_TAB_SUBJECT)`.

### `src/features/sql/LazySqlEditor.tsx` / `MonacoWrapper.tsx`

- The empty-buffer placeholder (scope call 2) is a Monaco `after`-content decoration on line 1,
  set and cleared from the same `onDidChangeModelContent` subscription that already writes the
  buffer to the store, and reading the registry at render time rather than at mount (so a file
  dropped after the editor mounted still names a real table) — no suggestion ranking, no card. Its
  text lives in `editorPlaceholder.ts` because `MonacoWrapper` cannot mount under jsdom (it needs
  real layout, as `SqlModule.test.tsx` already records) — the line's content is unit-tested there,
  the decoration itself is verified live like the rest of the editor.

## Non-goals

- **No chart re-added to Info, ever, by this leaf.** The `charts` tab is the destination for
  that; scope call 3 is final within this doc's scope.
- **No per-row "send to a new tab" shortcut on History.** Run (into console) plus the existing
  Pin is the whole path (scope call 6) — a direct history-to-tab action would be a second
  promotion mechanism next to `pinConsoleQuery`, which D73 deliberately keeps singular.
- **No ranking or card UI on the empty-console placeholder.** One static line, one table name —
  not `QuerySuggestions` under a new name.
- **No persisted "last active tab."** History opens like any other tab and follows the same
  keep-mounted/no-persistence contract every singleton already does; S6.9 is where persistence
  as a topic gets answered for the whole shell.

## Acceptance criteria

- [x] With nothing selected and the console never run this session, Info renders nothing at all
      — no scent strip, no output region — and the SQL pane occupies the drawer's full width
- [x] A selection opens Info showing only the scent strip; a console run (from the console's own
      Run or any S4 remote surface) opens Info showing only the result — neither shows the other
- [x] Info's tree contains no `AutoChartPanel` and no `QueryHistory` call site
- [x] The empty console shows a placeholder line naming an actually-loaded table, gone once the
      buffer has text
- [x] **Pin to tab** renders directly above `QueryOutput`'s Results header as the primary action;
      **History** and **Export recipe** render together, visually secondary to it
- [x] **History** opens a singleton tab (deduping to one instance across repeat clicks) whose
      content is the unmodified `QueryHistory` list
- [x] Clicking an old entry's Run button in the History tab runs it into the console, and Info
      shows the fresh result per this leaf's visibility rule — through the existing
      `runInConsole`, no new code path
- [x] Pin to tab on that fresh result behaves exactly as any console-run Pin does — no
      history-specific promotion path exists anywhere in the diff
- [x] `tsc -b` clean; full suite green; `oxlint` clean; `vite build` clean

## Definition of done

Opening the drawer with nothing selected and nothing run shows one thing: an inviting editor at
full width. A selection or a run is what earns Info its place, and once it has one, it holds
exactly the thing that earned it — a scent strip or a result, never a placeholder sentence
sitting on top of a real answer. Pin to tab is the one obvious next move above every result;
History moves from a footnote disclosure to a tab of its own, and an old query re-run from it
lands back in Info the same way any fresh run does — because it *is* the same run path, not a
second one built for history's sake. `tsc -b` / suite / `oxlint` / `vite build` clean.
